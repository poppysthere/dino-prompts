# AI 老师 Prompt 质量保障体系 —— 工作汇报与自动化方案

> 面向:管理层 / 开发团队 / AI 产品经理
> 日期:2026-07-14
> 仓库:dino-prompts(所有 prompt、测试用例、检查器均已版本化)

---

## 一、背景:为什么需要这套体系

我们的 AI 老师面向 4-7 岁、pre-A1/A1 级别的孩子,由小模型(gpt-5.4-mini)实时驱动。这个组合有三个天然难点:

1. **用户是幼儿。** 孩子会沉默、跑题、说母语、把话说错、被 ASR 转错——prompt 必须对每一种情况都有像真人老师一样的反应,而不是机械地推进流程。
2. **模型很小。** 小模型对抽象规则的服从度低,同一份 prompt 改一个词,行为可能整体变化。"改完感觉没问题"是不可靠的。
3. **一节课由十几个 prompt 模板串联**(热身、导入、单词页 x3、句子页 x5、收尾……),任何一页出问题,孩子的体验就断在那里——我们的留存数据已经证明了这一点(热身太长时,大量孩子在视频前流失)。

过去的做法是:改 prompt → 真人试课 → 看录屏挑毛病 → 再改。一轮要半天,而且只能覆盖"配合的孩子"这一种路径。**孩子不配合时的路径(沉默、拒绝、跑题、ASR 幻听)恰恰是最容易翻车、也最难人工复现的。**

因此我们搭建了一套 **prompt 评测流水线**:把每一个真实事故变成一条可自动重放的测试用例,让每次 prompt 修改在几分钟内跑完全部历史场景。

## 二、体系怎么运转:三层质量闭环

### 第 1 层:模板设计规范(写的时候就防住)

所有模板遵循统一契约,常见错误在设计层面就被禁止:

- **状态机脚本 + 有限自由度**:每一页写成固定的"beat"(台词行),模型只在"接住孩子的话"这一小步有自由(一句 6 词以内的 catch),之后必须回到脚本行。小模型跟例子不跟规则,所以每条规则都配正反例。
- **意义优先、语言无关**:判断孩子"说了什么"看意义不看语言——"不知道"“no sé”"몰라요"得到同样的处理。产品面向国际市场,规则里不允许绑死任何一种母语。
- **TTS 安全**:全部输出必须是词典词。禁止拉长拼写("Hiiii")、拟声笑("Hee hee")、省略号和破折号——这些都是真机上暴露过的发音事故。
- **防呆护栏**:垃圾姓名保护(`studentName` 是 "11"、"test_user" 时永不念出)、提问循环上限(同一问题最多问两次)、剧透保护(悬念页不许提前公布答案)、控制标签纪律(每条回复只有一个控制标签,且在末尾)。

### 第 2 层:自动化评测(改完就验证)

- **Case 电池(`eval/cases_*.yaml`)**:每页一组脚本化的"孩子输入序列",覆盖配合 / 沉默 / 拒绝 / 母语回答 / 跑题 / ASR 误听 / 垃圾姓名等路径。**目前 8 个电池、约 110 条用例。**
- **真实环境重放(runner)**:用例通过 Forge 调试 API 打到**和线上完全相同的模型与拼装方式**上,不是本地模拟。
- **机械检查器(`eval/checker_*.py`)**:对每条模型回复做结构断言——回复数量、台词行是否逐字、控制标签位置、TTS 安全、剧透、垃圾姓名、提问循环、每条用例专属的 forbid/require 短语。**规则是代码,不靠人眼。**
- **铁律:每一个线上事故都沉淀为回归用例。** 修复后该用例永远在电池里,同类问题不会静默复发。

### 第 3 层:线上日志挖掘(上线后继续学)

真实课堂日志按 classId 逐条分析,产出两种东西:

1. **prompt 能修的** → 当场改模板 + 加回归用例(如"好/OK 被当成跟读成功"的假表扬问题);
2. **prompt 修不了的** → 写成给开发的工单(`notes/dev_message_log_mining.md`),如 ASR 幻听词("From"“Yeah”"Sure"凭空出现)、静默计时器与孩子抢话的竞态、`studentName` 传了用户 ID 等,均附日志证据和配置修改建议。

## 三、实战战果(全部来自真实课堂日志)

| 线上事故 | 根因 | 修复 + 回归用例 |
|---|---|---|
| 老师把孩子叫成 "Tommy",孩子抗议后仍不改 | 档案默认名压过了孩子亲口说的名字 | "亲口说的名字永久生效"规则;`l1-name-*` 用例 |
| 奖励页大声念出 "test_user" | 模板未走公共层姓名规则 | 全模板垃圾姓名保护;`*-junkname` 用例 |
| "Are you happy today?" 连问 4 遍 | 无提问上限 | 同一问题最多两次 + 循环抗议应答;`question-loop` 检查器规则 |
| 孩子没说话,ASR 幻听出 "From.",老师开始讲解 from 的含义 | ASR 上下文配置鼓励"模糊音按英语猜" | 孤立英文词按噪声处理;并向开发提交了整套语言无关的 ASR 配置修订建议 |
| 孩子说"好",老师喊 "YES! You got it!" | 同意词被当成跟读成功 | "同意 ≠ 跟读"规则 + 重试一次上限;`*-agree-no` 用例 |
| "Of course." 触发无限重试循环 | "of course" 是 "horse" 的高频 ASR 误听 | 误听白名单 + "脚本只前进不后退";`horse-of-course-asr`、`horse-agree-loop` 用例 |
| 孩子学马叫被转写成"奶奶",老师当成"有趣的声音" | 中文 ASR 把 neigh 写成奶奶 | 误听白名单写进台词行;`horse-nainai-asr` 用例(今日修复,已全绿) |
| TTS 念不出 "Hiiii" / "Hee hee",破折号断句怪异 | 非词典拼写 | 全库清理 + `tts-stretched`/`tts-giggle` 检查器规则 |
| 热身太长,孩子在视频前大量流失 | 流程问题 | 热身从 5 问砍到 3 问,沉默阶梯 2 级封顶;电池全量回归验证 |

**当前状态:24 个模板、约 110 条用例、6 个检查器,L2 demo 课全链路(热身 → 导入 → cow/cat/horse 单词页 → 5 步句子链 → 收尾)全部通过。**

## 四、下一步:全自动评测计划

现在"跑电池"这一步已经是自动的,但**触发**还靠人。计划分四期把人从循环里逐步解放:

**Phase 1 — CI 门禁(1-2 周,收益最大)**
GitHub 上每次 prompt 提交自动触发:全量电池 → 检查器 → 生成通过/失败报告,不绿不合入。需要开发提供一个可从 CI 访问的 Forge 调试 API token。

**Phase 2 — LLM 评审员补上"温度"维度(2-3 周)**
机械检查器管"对不对",再加一个大模型评审员按量表打分"像不像真人老师":是否接住了孩子的情绪、是否答非所问、能量是否匹配。分数入库,按版本看趋势,防止"结构全对但越改越冷冰冰"。

**Phase 3 — 线上日志自动挖掘(3-4 周,需开发配合)**
每日拉取课堂日志,自动标记异常模式:同一问题连问 ≥3 次、念出疑似 ID 的姓名、输出含 TTS 危险拼写、会话未以正常标签结束、疑似 ASR 幻听(静默期冒出孤立英文词)。命中的日志自动转成候选回归用例,人工确认后入库。**这一步把"用户替我们测试"变成"日志替我们写用例"。**

**Phase 4 — 新页面量产模板(持续)**
cow/cat/horse 三页已验证"同一骨架换词"的模式可行。后续新单词页 = 填一张词表(词、拟声、动作标签、ASR 误听白名单)→ 自动生成模板草稿 + 电池 → CI 验证。产能从"天"降到"小时"。

**需要的支持:** Forge API 的 CI 访问权限(Phase 1)、课堂日志导出接口(Phase 3)、以及 ASR 配置修订(工单已在 `notes/dev_message_log_mining.md`,与本体系互补——prompt 只能兜住 ASR 的错,不能消灭它)。
