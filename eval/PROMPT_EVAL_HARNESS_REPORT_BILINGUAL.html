1. How the Evaluation Harness Works 评测 Harness 如何工作

Executive summary 管理层摘要： The harness is not a collection of manual test chats. It is a repeatable software system that controls prompt source, test inputs, model routing, evidence capture, evaluation rules, and release decisions.
Harness 不是一组人工随意聊天，而是一套可重复的软件系统：统一控制 Prompt 来源、测试输入、模型调用、证据留存、评判规则与发布决策。

1.2 What happens in one model call 一次模型调用如何发生

  1. Load the exact common rule, stage template, render content, and runtime variables加载指定公共规则、阶段模板、渲染内容与运行时变量
  2. Authenticate once from environment variables and preflight that the selected model exists从环境变量完成一次认证，并预检所选模型确实可用
  3. Send systemPrompt, conversation messages, providerName, and modelName to Prompt Forge's debug API向 Prompt Forge Debug API 发送 systemPrompt、对话 messages、providerName 与 modelName
  4. Play the scripted child behavior turn by turn and capture every teacher response逐轮执行儿童行为脚本，完整采集老师的每次回复
  5. Save the transcript first, then run stage-specific rules and quality checks先保存原始对话证据，再执行阶段专属规则与质量检查
  6. Aggregate counts and exit codes; fail the run if any case fails or any expected transcript is missing汇总数量与退出码；任何用例失败或预期记录缺失，整次运行即失败

Operational safety: credentials are read only from process environment variables, never committed to Git or written into reports. Transient network and upstream failures are retried with limits. Resume is allowed only when the saved model, prompt version, and source hashes still match. 运行安全：凭证只从进程环境变量读取，绝不提交到 Git 或写入报告。瞬时网络与上游错误采用有限重试；只有模型、Prompt 版本与源文件哈希完全一致时才允许续跑。
Separation of concerns: the harness sends local, versioned prompts to Prompt Forge's debug API; it does not edit or deploy Prompt Forge content. 2. The Regression Pipeline 回归闭环 —— 每个问题如何变成标准

Core idea 核心思想： Every issue found in a real lesson is reproduced as a regression case, repaired in the template, protected by a mechanical checker, and retested on the live model before release.
每一个真实课堂问题都会被复现为回归用例、在模板中修复、由机械检查器永久守护，并在发布前使用真实模型重新验证。
  1. Real device transcript reveals a bug真机课堂录音/记录中发现 bug
  2. Reproduce it as a regression case (eval/cases_*.yaml, device ID in the note)复现为回归测试用例（备注中记录设备 ID）
  3. Fix the template (prompts/**)修复 prompt 模板
  4. Add a mechanical checker rule so the bug CLASS can never silently return添加机械检查规则，使这一类 bug 永远无法悄悄复发
  5. Run the full live battery through Prompt Forge on the selected target model通过 Prompt Forge 在所选目标模型上运行完整测试套件
  6. Size lint — every template has a hard line + word budget体积检查 —— 每个模板都有行数/字数硬预算
  7. Commit + push — every fix versioned on GitHub with reasoning提交推送 —— 每个修复都带原因说明，版本化管理
Two disciplines keep this honest · 两条纪律保证可信度：
  • Anti-bloat 防膨胀： Every template has a line/word budget. A fix must usually pay for itself by trimming elsewhere. 每个模板有行数/字数预算，加东西通常要在别处删掉等量内容；只有结构性变更才能提高预算，且必须写明原因。
  • Flakiness testing 抗随机性测试： Fixed cases are re-run 3–4 times before we trust them — LLMs fail intermittently. 修好的用例连续重跑 3–4 次才算通过 —— LLM 会间歇性失败，一次通过说明不了问题。

3. The Standards 标准 —— 按课程页面分类的检查器

Every model reply is evaluated by named checker rules; violating any rule fails the case. The rules below are grouped by lesson stage.
每一条模型回复都会经过命名检查规则；违反任一规则即判定用例失败。以下按课程阶段分组。

4. The Mock Kids 模拟儿童 —— 测试时我们扮演谁

Tests simulate real children, not ideal students. Each case represents one behavior pattern, including silence, another language, confusion, questions, or playful off-topic speech. The checker evaluates whether the teacher responds helpfully and continues naturally.
测试模拟的是真实孩子，而不是理想学生。每个用例代表一种行为，包括沉默、使用其他语言、迷茫、提问或玩闹跑题；检查器评判老师是否提供帮助并自然推进。
Kid 孩子类型How they behave 测试中的表现What the prompt must do 要求 prompt 做到
Happy-path kid顺利型孩子Answers correctly, says "yes!", plays alongCelebrate specifically, keep moving — no dwelling有针对性地庆祝（不能泛泛夸），然后推进，不拖沓
Silent kid沉默的孩子Says nothing; system injects "silent for 5 seconds", sometimes twiceRe-ask shorter → two-option choice → move on. Never repeat verbatim, never celebrate an answer that never came简短重问 → 二选一 → 优雅推进。绝不原句重复，绝不庆祝一个不存在的回答
Lost/confused kid迷茫的孩子"什么？", "我听不懂", "我不会"HELP, do not repeat louder: comfort, model a tiny answer, and give one clear next action帮忙而不是更大声重复：先安抚，再示范一个最短答案，并给出一个清楚的下一步指令
Chinese-only kid只说中文的孩子"我很开心！", "小猫！", "不知道"React to the MEANING in easy English; never echo Chinese, never treat L1 as a wrong answer用简单英文回应“含义”；不复读中文、不翻译、绝不把说母语当成答错

Scared kid害怕的孩子"我怕。""It's okay. I'm here." first — the page still flows, gently先说“没事，我在” —— 页面仍温和地继续
Opt-out kid拒绝开口的孩子"我不想说。" (twice)Respected instantly. No third invite, no "just try!", no guilt立即尊重。不第三次邀请、不说“试一下嘛”、不制造内疚。拒绝是神圣的

5. The Teaching Doctrines 教学信条 —— 规则背后的人性标准

These are the human standards enforced by the checkers. They come from real lesson moments in which the avatar sounded robotic or failed to help the child.
这些是检查器强制执行的“人的标准”，来自真实课堂中虚拟老师显得机械、或没有真正帮助孩子的时刻。
1. Recast, never correct 重述，绝不纠错
Any attempt is a win. Say the natural version back as a warm response; never say “You should say...”
这个年龄任何开口都是胜利。把正确版本当成开心的回应说回去，绝不说“你应该这样说”。
2. Feed the words 直接喂词
A stuck child may want to answer but lack the words. Offer a tiny model or choice; imitation still counts.
卡住的孩子可能想回答但没有词。给一个最短示范或选项；跟读也算回答。
3. Answer first 先回答孩子
When the child asks the teacher something, answer like a person first, then return to the lesson.
孩子反问老师时，老师先像真人一样回答，再把话轮接回课堂。
4. The counter law 计数法则
The teacher's reply count controls the beat. A child's extra words do not create an endless page.
老师自己的回复数决定节拍。孩子说得再多，也不能让页面无限延长。
5. Say nothing twice 绝不重复
Do not repeat a sentence, question, or response on the same page. Repetition sounds robotic.
同一页里任何句子、问题、回应都不说第二遍。重复听起来像坏掉的机器人。
6. Invite budget 邀请预算
Invite the child to speak no more than twice: one ask and one supported retry.
最多邀请孩子开口两次：一次正常邀请，一次带帮助的重试。
7. Opt-out is sacred 尊重拒绝
“I don't want to say it” ends the pressure immediately and warmly.
孩子说“我不想说”后，老师应立即、温暖地停止追问。
8. Wait is a job 等待即任务
Every wait gives the child one clear, tiny, answerable action.
每一次等待都要给孩子一个清楚、微小、答得上的任务。
9. Answerable questions 孩子答得上的问题
Use concrete choices when an open question is too difficult: “A cat? Or a dog?”
开放问题太难时，改用具体选项：“A cat? Or a dog?”
10. Matched catches, no fake praise 真实回应，不假夸
The reply must show that the teacher heard the child; praise must match what actually happened.
回复必须证明老师听见了孩子；夸奖必须符合孩子实际完成的事情。
11. Small win first 先赢一次
The first action is a simple “hi”, giving the child an easy, safe start.
第一个动作只是简单地说 “hi”，让孩子安全、轻松地开始。
12. TTS-safe, English-only 语音安全、纯英文输出
Every written character will be spoken by the English voice engine, so output must be clean and speakable.
每个写出的字符都会被英文语音引擎朗读，因此输出必须干净、可自然朗读。
