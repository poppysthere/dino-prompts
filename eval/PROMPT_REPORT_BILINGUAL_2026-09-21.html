1. The Fix Pipeline 修复流程 —— 每个 bug 如何变成标准

Core idea 核心思想： Every issue found in a real lesson is reproduced as a regression case, repaired in the template, protected by a mechanical checker, and retested on the live model before release.
每一个真实课堂问题都会被复现为回归用例、在模板中修复、由机械检查器永久守护，并在发布前使用真实模型重新验证。
  1. Real device transcript reveals a bug真机课堂录音/记录中发现 bug
  2. Reproduce it as a regression case (eval/cases_*.yaml, device ID in the note)复现为回归测试用例（备注中记录设备 ID）
  3. Fix the template (prompts/**)修复 prompt 模板
  4. Add a mechanical checker rule so the bug CLASS can never silently return添加机械检查规则，使这一类 bug 永远无法悄悄复发
  5. Run the full live battery through Prompt Forge on the target production model (current L3 V2: GPT-5.6 Luna)通过 Prompt Forge 在目标生产模型上跑完整测试（当前 L3 V2：GPT-5.6 Luna）
  6. Size lint — every template has a hard line + word budget体积检查 —— 每个模板都有行数/字数硬预算
  7. Commit + push — every fix versioned on GitHub with reasoning提交推送 —— 每个修复都带原因说明，版本化管理
Two disciplines keep this honest · 两条纪律保证可信度：
  • Anti-bloat 防膨胀： Every template has a line/word budget. A fix must usually pay for itself by trimming elsewhere. 每个模板有行数/字数预算，加东西通常要在别处删掉等量内容；只有结构性变更才能提高预算，且必须写明原因。
  • Flakiness testing 抗随机性测试： Fixed cases are re-run 3–4 times before we trust them — LLMs fail intermittently. 修好的用例连续重跑 3–4 次才算通过 —— LLM 会间歇性失败，一次通过说明不了问题。

4. The Teaching Doctrines 教学信条 —— 规则背后的人性标准

These are the human standards enforced by the checkers. They come from real lesson moments in which the avatar sounded robotic or failed to help the child.
这些是检查器强制执行的“人的标准”，来自真实课堂中虚拟老师显得机械、或没有真正帮助孩子的时刻。
1. Recast, never correct 重述，绝不纠错
Any attempt is a win. Say the natural version back as a warm response; never say “You should say...”
这个年龄任何开口都是胜利。把正确版本当成开心的回应说回去，绝不说“你应该这样说”。
2. Feed the words 直接喂词
A stuck child may want to answer but lack the words. Offer a tiny model or choice; imitation still counts.
卡住的孩子可能想回答但没有词。给一个最短示范或选项；跟读也算回答。
3. Answer first 先回答孩子
When the child asks the teacher something, answer like a person first, then return to the lesson.
孩子反问老师时，老师先像真人一样回答，再把话轮接回课堂。
4. The counter law 计数法则
The teacher's reply count controls the beat. A child's extra words do not create an endless page.
老师自己的回复数决定节拍。孩子说得再多，也不能让页面无限延长。
5. Say nothing twice 绝不重复
Do not repeat a sentence, question, or response on the same page. Repetition sounds robotic.
同一页里任何句子、问题、回应都不说第二遍。重复听起来像坏掉的机器人。
6. Invite budget 邀请预算
Invite the child to speak no more than twice: one ask and one supported retry.
最多邀请孩子开口两次：一次正常邀请，一次带帮助的重试。
7. Opt-out is sacred 尊重拒绝
“I don't want to say it” ends the pressure immediately and warmly.
孩子说“我不想说”后，老师应立即、温暖地停止追问。
8. Wait is a job 等待即任务
Every wait gives the child one clear, tiny, answerable action.
每一次等待都要给孩子一个清楚、微小、答得上的任务。
9. Answerable questions 孩子答得上的问题
Use concrete choices when an open question is too difficult: “A cat? Or a dog?”
开放问题太难时，改用具体选项：“A cat? Or a dog?”
10. Matched catches, no fake praise 真实回应，不假夸
The reply must show that the teacher heard the child; praise must match what actually happened.
回复必须证明老师听见了孩子；夸奖必须符合孩子实际完成的事情。
11. Small win first 先赢一次
The first action is a simple “hi”, giving the child an easy, safe start.
第一个动作只是简单地说 “hi”，让孩子安全、轻松地开始。
12. TTS-safe, English-only 语音安全、纯英文输出
Every written character will be spoken by the English voice engine, so output must be clean and speakable.
每个写出的字符都会被英文语音引擎朗读，因此输出必须干净、可自然朗读。

5. Progression 进展 —— 真机 bug 如何变成永久标准

Each row comes from a real lesson record: discover the issue → reproduce it as a case → repair the prompt → lock the behavior with a permanent checker rule.
